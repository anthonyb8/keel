# investigation

Answer a question about the code or its history, read-only, with every claim cited.

## Steps

1. Stay read-only: no worktree, no edits.
2. Answer from the code, the git history (`git log -S`, `git blame`) and Linear (`keel linear get`), citing `path:line` and commits for every claim, and labelling each claim as measured, read or inferred.
3. Give a choice between options a recommendation with a tradeoffs table.
4. If the answer turns into a change, stop and re-route to bug-fix or issue.

## Reply

The answer first, then the evidence.
